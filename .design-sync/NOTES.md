# design-sync notes — @ornie/react

## Repo facts
- Own-source repo (package not in node_modules): converter needs `--entry dist/index.js`; `--node-modules ./node_modules`.
- `buildCmd: pnpm run build` (tsup + esbuild CSS). pnpm + nvm (node 24 via `.nvmrc`); never npm for the repo itself (`.ds-sync/` converter deps are the isolated exception).
- Storybook 8 (react-vite) at repo root `.storybook/`; reference build lives at `.design-sync/sb-reference` (gitignored, rebuild with `npx storybook build -c .storybook -o .design-sync/sb-reference` whenever src or stories change).
- `.storybook/preview.tsx` decorator wraps stories in `<div className="ornie-app">`. As of the 2026-07-10 sync the converter's decorator esbuild pass can NO LONGER auto-bundle it — `preview.tsx` imports `index.css` which `@import`s `fonts.css` (Manrope `.woff2`), and the decorator bundler (`source-storybook.mjs:313`) has no font loader → `! preview decorator bundle failed: No loader is configured for ".woff2"`. Without the wrapper, previews lose the base Manrope font/ink/bg that `.ornie-app` (base.css) provides by inheritance (design tokens are on `:root`, so components still style themselves — only the inherited page font/ink/bg is lost). Fixed via `cfg.provider` (see Fixes 2026-07-10). Do NOT expect decorator auto-bundling to work.
- No remote assets anywhere: Avatar's image story uses an inline data-URI SVG by design, all fonts vendored (Manrope woff2 in `src/fonts/`). The `[ASSETS_BLOCKED]` canary has nothing to bite on in this repo.

## Fixes applied (re-sync 2026-07-10 — Phases 2–4 added, 18→57 components)
- **[GENERAL] Preview wrapper is now `cfg.provider`, not the auto-bundled decorator.** The decorator bundle fails (woff2 loader gap — see Repo facts). Fix: `.design-sync/preview-shell.mjs` exports `OrnieApp = ({children}) => <div className="ornie-app">{children}</div>`, bundled via `cfg.extraEntries: ["./.design-sync/preview-shell.mjs"]` and referenced by `cfg.provider: {"component":"OrnieApp"}`. Produces DOM identical to the decorator; `--ornie-bg` = `--ornie-sand-50` = `#f8f5f1` = the storybook 'ornie' canvas, so backgrounds are pixel-identical. This re-keys every component's grade contract (provider is in the sourceKey), so this sync re-verified all 57; future syncs carry forward with the provider baked in. Also generates concrete README/prompt wrap guidance (decorator-only shipped a generic note). NEVER per-component-fix a missing wrapper — it's this one global.
- `[GRID_OVERFLOW]` wide (→ `cardMode: "column"`) added this sync: Button, Dock, Icon, TaskRow, TopBar, MetaLine (join Card/Radio/Switch/Tabs from 2026-07-03). MetaLine only surfaced AFTER the provider fix — the real Manrope font is wider than the fallback the broken decorator left, so content that fit before now overflows. Expect more of these if new wide/tabular stories are added.
- Button now has 10 stories (was 9), Card 8 — compare default cap is 6. Capture with `--max-stories 12` to cover all tails (Button: Loading/Disabled/Full Width/Deprecated Icon Props; Card: Profile Example/Paddings). All graded match 2026-07-10.
- CommandOverlay/Sheet/PanelDrawer stories render the CLOSED trigger/rest state (open panel is interaction-gated). No `[PORTAL?]`/`escape` flagged → no `cardMode: single` needed (unlike Modal). Open-panel fidelity unverified by compare — see Re-sync risks.
- Modal now skips THREE portal stories (was 2): `components-modal--confirmation`, `components-modal--with-form`, `components-modal--top-placement` — all `createPortal(document.body)` open-modal stories that leave `#storybook-root` empty (sb-error "no storybook root content"). They render live; the root-scoped capture can't see them. `compare.mjs`'s `fullyGraded` check needs EVERY story (sb-error ones included) skipped or graded, so a new open-modal story MUST be added to this skip list or Modal never reaches carried-forward. Capturable stories (Interactive, Initial Focus) grade match.
- Tooltip's `Controlled Open` story DOES exercise the bubble (pinned open) and it graded match — so bubble styling is NOT entirely unverified anymore (the hover-only Placements/Long Content/With Shortcut stories still show rest-state triggers only).
- **[REFERENCE_STALE?] is a benign false alarm on this re-sync flow and confused two subagents.** It fires because the bundle is rebuilt (package-build) AFTER `sb-reference`, so their build-base-shas differ — but BOTH derive from the SAME committed src (verified 2026-07-10: git working tree clean for src/dist/tokens.json; newest src mtime < dist mtime < sb-reference mtime). The reference is current; ignore the warning UNLESS git shows uncommitted src changes or sb-reference predates a src edit.
- **Motion foundation card is a terminal `close`, do NOT re-chase it.** `Foundations/Motion` (and to a lesser degree Elevation) resolve token values live via `getComputedStyle` (shared.tsx `TokenValue`). The shipped `_ds_bundle.css` serializes motion tokens differently than the dev `styles.css` storybook loads: `--ornie-duration-spin` `.9s`→`900ms`, cubic-bezier `.2`→`0.2` (leading zeros). Semantically identical; only the displayed value TEXT differs. Not fixable from a preview (value comes from the loaded CSS; faking it defeats the oracle). Elevation graded match (leading-zero only, below threshold); Motion graded close.
- Foundations previews capture at a fixed viewport height and clip tall content below the fold (ColorPalette Layer-2 roles, DarkMode footer chips, TypeScale weights) — framing only; all visible overlapping content matched. Read raw/ PNGs if a foundation sheet looks truncated.
- RedactedBars skips 4 standalone-bar stories (`components-redactedbars--{default,organic-list,fixed-two-bars,fixed-three-bars}`) — the bars are very-low-contrast fills on a transparent bg with no wrapping surface, so storybook's content detector reads `#storybook-root` as empty (sb-error "no storybook root content"). The bars DO render (verified in context via `Burrow Locked Entry`, which wraps them in a card + SealBadge and grades match). If a new standalone RedactedBars story is added, it will need the same skip. Redaction confirmed obscuring (faint bars, no readable text).

## Dark mode + Foundations (added 2026-07-05)
- Dark theme = `[data-ornie-theme='dark']` Layer-2 override in tokens.css, attribute-only by design. The dark block must stay AFTER the light block (specificity tie, source order wins). `scripts/check-contrast.mjs` is the WCAG gate over both themes — run it after any token change.
- Card.css elevated border now uses `--ornie-border-subtle`; Avatar tone chips have dark-scoped dim overrides in Avatar.css.
- Foundations components live in `src/foundations/` (ColorPalette, TypeScale, SpacingScale, RadiusScale, Elevation, DarkMode), story titles `Foundations/<ExportName>`, shared CSS `foundations.css`.

## Re-sync risks
- **Modal's open-modal rendering is outside the compare oracle** (skipped stories). If Modal.css or Modal.tsx changes, re-verify manually: serve `ds-bundle` and screenshot `components/components/Modal/Modal.html?story=Confirmation` vs the live storybook page for `components-modal--confirmation` (full-page shot, not root-scoped).
- Tooltip bubble styling (`.ornie-tooltip__bubble`) is likewise unverified by compare (hover-only). If Tooltip.css changes, eyeball the bubble manually.
- Button stories beyond the default cap re-verify only if `--max-stories 9` is passed on a scoped compare after Button story/source changes.
- `conventions.md` names real tokens/props (validated 2026-07-03 against the build: `.ornie-app`, Layer-2 `--ornie-*` set, Card/Badge/Avatar props). If components or tokens are renamed, re-run that validation — the header rots silently otherwise.
- sb-reference and dist must move together: rebuild both when src changes, or `[REFERENCE_STALE?]` grades against the old design.
- **Dark-theme rendering is verified only via the `DarkMode` foundations card** (per-component dark stories were deliberately not added). A token change in the dark block re-verifies through that one card — eyeball it, don't sibling-trust it.
- Foundation card labels resolve hex values at runtime via `getComputedStyle` — if a swatch shows an empty value, the token was renamed/removed; the swatch itself (the `var()` background) goes transparent. `ColorPalette`'s scale arrays are hardcoded — update them when Layer-1 stops change.
- `scripts/check-contrast.mjs` parses tokens.css with regex block-matching — if the file's block structure changes (selectors renamed, nesting added), the script needs updating too.
